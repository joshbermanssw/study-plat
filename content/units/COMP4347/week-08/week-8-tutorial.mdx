## Summary

This Week 8 tutorial integrates Mongoose into an Express MVC app, exercising the model layer against a Wikipedia revisions dataset — direct practice for the Week 7 lecture content.

- Adding Mongoose: `npm install mongoose` (or `npm install` against an existing `package.json`) and connecting via `mongodb://localhost/<dbname>`.
- Writing Mongoose queries that mirror the Mongo shell syntax: `find`, `update`, `aggregate` on the `revisions` collection.
- Full MVC layout: views (`titleForm.pug`, `revision.pug`), model (`revision.js` schema + `db.js` connection), controller (`revision.server.controller.js`), router (`revision.server.routes.js`).
- Static model methods (e.g. `findTitleLatestRev`) callable from controllers, with controller-supplied callbacks handling the result.
- Implementing the missing route file to bind controller methods to URLs and starting the app with `node ./revserver.js`, then hitting `localhost:3000/revision`.

Exam focus: complete a missing piece of an MVC Express+Mongoose app (typically the route file); write a Mongoose static method for a stated query; trace the request flow from URL through router/controller/model back to the view.

Part 4: Introduction to Promise Library Node.js naturally does not block IO as other mainstream programming languages do. In that case, if you want to write some code based on the output of previous function, you cannot just put the statement at the following line. Alternatively, you should use callback functions to chain the following codes with the previous function. Most node core modules such as ‘fs’ module embrace this style in a nutshell. When your logic gain complex, there will be a lot of layers of callback function. The term “callback hell” is coined to describe this situation.
