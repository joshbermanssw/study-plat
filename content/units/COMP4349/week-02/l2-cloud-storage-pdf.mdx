## Summary

Week 2 covers AWS cloud storage with a deep focus on S3 as a distributed object store, contrasted with EBS, EC2 instance store, and EFS — the storage foundation for later compute, database, and serverless topics.

- **Storage type matrix**: S3 (object, unlimited, high latency, cheapest), EBS SSD (block, network-attached, 16 TiB), Instance Store (block, ephemeral, lowest latency), EFS (NFSv4.1 file, multi-attach). Object stores update whole objects; block stores update bytes.
- **S3 fundamentals**: flat bucket + key namespace (pseudo folders via key prefixes), globally unique bucket names, virtual-hosted URL style, 11 nines durability via multi-AZ replication within a Region.
- **Storage classes**: Standard, Intelligent-Tiering, Standard-IA, One Zone-IA, Glacier Instant/Flexible/Deep Archive — differ in AZ count, retrieval cost, and minimum storage duration. Lifecycle policies transition or expire objects.
- **Versioning vs replication**: versioning protects against accidental overwrite/delete (adds delete markers); cross-Region replication requires versioning on both buckets and is for DR/compliance/latency.
- **Consistency**: strong read-after-write for all PUT/GET/LIST/DELETE.

**Exam focus**: pick the right storage class for an access pattern/cost trade-off, and reason about versioning + replication behaviour when delete markers or version IDs are involved.
