## Summary

Week 10 covers OS-level virtualization (containers), Docker, microservice architecture, and Amazon ECS — the container-orchestration leg of modern cloud applications.

- **Containers vs VMs**: containers share the host kernel and use Linux namespaces (mnt/pid/uid) for isolation and cgroups for resource limits — lower start latency and overhead than VMs, weaker isolation. KVM runs a separate guest kernel; containers do not.
- **Docker**: images = layered, read-only templates defined by a Dockerfile; pushed to a registry (ECR). Containers add a thin writable layer. Persist data via volumes/bind mounts/tmpfs. Networking modes: host, bridge (default, with NAT + port mapping), none, overlay.
- **Microservices**: decompose monoliths into independently deployable services exposing REST APIs; scale and fail per service rather than per host.
- **Amazon ECS**: cluster + task definition (image, CPU, memory, ports) + service (desired count) + ALB target groups. Dynamic port mapping lets multiple containers per EC2 share a host with ALB tracking ephemeral ports. Compute options: EC2 launch type, Fargate (serverless), Lambda. EKS = managed Kubernetes alternative.
- **Service discovery**: ECS Service Discovery via Cloud Map + Route 53, ECS Service Connect, or AWS App Mesh.

**Exam focus**: contrast containers vs VMs vs microVMs, and design an ECS architecture (task def + service + ALB target group + ASG) showing how dynamic port mapping and health checks support container-level scaling.
