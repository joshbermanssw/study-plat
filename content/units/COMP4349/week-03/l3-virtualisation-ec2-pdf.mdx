## Summary

Week 3 covers server virtualization theory and Amazon EC2 as the canonical IaaS compute service — the foundation of cloud-rented compute resources and the basis for later auto-scaling and container topics.

- **Virtualization**: transparent emulation of an IT resource. Type 1 (bare-metal: Xen, Hyper-V, KVM) vs Type 2 (hosted). Hypervisor schedules vCPUs on pCPUs, isolates guest memory via two-level page tables, and arbitrates I/O.
- **Hypervisor examples**: Xen (Dom0 + guest domains), Hyper-V (root/child partitions), KVM (Linux kernel + QEMU + libvirt — used by AWS and GCP).
- **EC2 launch choices**: AMI, instance type (family/generation/size, e.g. t3.large), key pair, VPC/subnet, security group, storage (EBS persistent vs ephemeral Instance Store vs EFS/FSx for shared), IAM role, user-data script, tags.
- **AWS Nitro System**: HVM hypervisor + Nitro cards offload VPC networking, EBS, security and monitoring to dedicated hardware; bare-metal instances skip the hypervisor but still use Nitro cards.

**Exam focus**: choose the correct instance type and storage option for a workload (compute- vs memory- vs storage-optimised; EBS vs Instance Store persistence), and explain how a hypervisor isolates CPU/memory/I-O between guests.
