## Summary

Week 4 introduces VPC networking fundamentals plus managed relational databases on AWS — RDS for cloud-hosted DB engines and Aurora as a cloud-native, distributed SQL service.

- **VPC + Security Groups**: CIDR blocks define IP ranges; subnets sit in one AZ; security groups are stateful instance-level firewalls with allow-only rules (source can be a CIDR or another SG).
- **EBS recap**: block storage attached over the network to a single EC2 instance, replicated within an AZ, persists beyond instance termination (root volume DeleteOnTermination defaults true).
- **RDS**: managed engine (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Aurora). Multi-AZ uses synchronous replication for HA/failover; Read Replicas use asynchronous replication for read scaling.
- **Aurora architecture**: disaggregates compute (1 writer + up to 15 readers running modified MySQL/PG) from a distributed storage layer with 6-way replication across 3 AZs, write quorum 4/6, read quorum 3/6. "The log is the database" — only redo log records cross the network; storage nodes materialise pages asynchronously.
- **LSN/VCL/VDL**: track durability boundaries and transaction consistency points during crash recovery.

**Exam focus**: design a VPC subnet + security-group topology for an EC2->RDS app, and compare Multi-AZ (HA) vs Read Replicas (scalability) vs Aurora's quorum-based storage for durability.
