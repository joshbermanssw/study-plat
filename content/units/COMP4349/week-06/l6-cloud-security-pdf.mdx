## Summary

Week 6 covers AWS cloud security: the shared responsibility model, IAM users/groups/roles/policies, attribute-based access control, and federated identity — the authn/authz backbone for everything else in the unit.

- **Shared responsibility**: AWS secures *of* the cloud (physical, hypervisor, network); customer secures *in* the cloud (OS patching for EC2, SG rules, IAM, app config, data encryption). Managed services (RDS, Lambda) shift more to AWS; SaaS shifts the most.
- **IAM primitives**: users (long-term keys), groups (collection of users), roles (assumed via STS for temp credentials — used by EC2 instance profiles, cross-account access, federated users), policies (identity- or resource-based JSON).
- **Policy evaluation**: implicit deny by default; explicit allow overrides default deny; explicit deny always wins. Document has Version, Statement, Effect, Action, Resource (ARN), optional Condition.
- **ABAC vs RBAC**: tag-based conditions (aws:ResourceTag, aws:PrincipalTag) scale better than per-resource role policies.
- **Federation**: SAML/OIDC IdPs + STS issue temporary credentials; IAM Identity Center for workforce SSO; Cognito user pools (authn) + identity pools (AWS authz) for app users.

**Exam focus**: read an IAM JSON policy and predict the access decision (including conditions and tag matches), and assign responsibility (AWS vs customer) for security tasks across IaaS/PaaS/SaaS scenarios.
