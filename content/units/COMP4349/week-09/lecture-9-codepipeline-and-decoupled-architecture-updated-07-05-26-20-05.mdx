## Summary

Week 9 combines DevOps CI/CD on AWS (CodePipeline) with decoupled application architecture using SQS and SNS — moving from tightly-coupled monoliths to scalable, fault-tolerant cloud designs.

- **DevOps + CI/CD**: continuous integration (frequent merges + automated build/test), continuous delivery (auto-release to repo), continuous deployment (auto to prod). AWS toolchain: CodeCommit/GitHub (source), CodeBuild (build/test), CodePipeline (orchestration), CodeDeploy/CloudFormation (deploy).
- **CodePipeline**: a pipeline has stages (Source -> Build -> Deploy), each containing actions; one failed action stops execution. Safer infra pipelines use change sets + manual approval before applying CloudFormation updates; validate with `cfn-lint` and `validate-template`.
- **Decoupling**: tight coupling = scaling and failure pain. Microservices + LBs + async messaging break dependencies.
- **Amazon SQS** (point-to-point, pull): Standard (at-least-once, best-effort order) vs FIFO (exactly-once, ordered). Configurable visibility timeout, short/long polling, DLQ for poison messages. Producer puts, consumer pulls and explicitly deletes.
- **Amazon SNS** (pub/sub, push): topics fan out one message to many subscribers (SQS, Lambda, email, HTTP, SMS). Common fan-out pattern: S3 event -> SNS -> multiple SQS queues -> worker fleets.

**Exam focus**: design a decoupled image-processing pipeline (S3 -> SNS -> SQS -> EC2/Lambda) including the right IAM/resource policies, and contrast SQS vs SNS delivery semantics.
