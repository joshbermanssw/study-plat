## Summary

Week 8 introduces cloud automation: the AWS CLI for programmatic API calls and CloudFormation as the AWS Infrastructure-as-Code service for reproducible, version-controlled environments.

- **AWS CLI**: terminal access to the same APIs as the Console/SDKs; authenticated via access key ID + secret. Examples: `aws ec2 run-instances`, `aws s3 cp`, `aws cloudformation create-stack`.
- **IaC benefits**: reusability, repeatability, maintainability — avoids manual-process risks (no audit trail, no rollback, inconsistent configs). A *stack* is the running collection of resources created from a template.
- **CloudFormation template anatomy** (YAML or JSON): `AWSTemplateFormatVersion`, `Description`, `Parameters`, `Mappings`, `Conditions`, `Resources` (the only required section), `Outputs`. Each resource has Type (e.g. `AWS::EC2::Instance`) and Properties.
- **Intrinsic functions**: `!Ref` returns parameter value or resource ID; `!GetAtt` reads resource attributes (e.g. `EC2Instance.PublicDnsName`); `!Sub` for variable substitution. `DependsOn` enforces creation order.
- **Stack lifecycle**: `create-stack`, `update-stack`, `delete-stack`; debug via stack events (e.g. `Ref` on a SG without VpcId returns name not ID — common error).

**Exam focus**: read or write a CloudFormation template snippet to provision VPC/EC2/RDS resources, and explain stack vs template, parameters vs outputs, and how intrinsic functions wire resources together.
