## Summary

Week 5 dives into AWS VPC networking — CIDR design, routing, public/private subnet patterns, layered security, and private connectivity to managed services via PrivateLink.

- **VPC + subnets**: VPC CIDR between /16 and /28; subnets sit in one AZ with non-overlapping CIDRs and AWS reserves 5 IPs per subnet. Public IPs via auto-assign or Elastic IP; ENIs are reattachable virtual NICs.
- **Routing**: route tables map destination CIDR -> target (local, IGW, NAT, VPC endpoint). Most-specific match wins. Public subnet = route 0.0.0.0/0 -> IGW; private subnet = 0.0.0.0/0 -> NAT gateway for outbound-only internet.
- **Gateways**: IGW (two-way, one per VPC, no IP); NAT Gateway (outbound only, in a public subnet, per-AZ for HA, has EIP).
- **Defence in depth**: stateful security groups at the ENI/instance level (allow-only) vs stateless network ACLs at the subnet level (allow + deny, numbered rule order). Bastion host pattern for SSH into private subnets.
- **PrivateLink + VPC endpoints**: interface endpoints (ENI with private IP, billed) keep S3/managed-service traffic on the AWS network; gateway endpoints (free) for S3 and DynamoDB via route-table prefix lists.

**Exam focus**: design a multi-AZ VPC with correct public/private subnets, route tables and NAT, and contrast security groups vs NACLs vs gateway/interface endpoints for a given access requirement.
