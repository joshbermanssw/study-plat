Computing 4 Innovation (INFO4444) School of Computer Science Week 6 – In-Class Activity Build a Small App with AI as Your Copilot Session purpose In this class, you will work in small teams to design and prototype a simple digital product. The goal is not just to make something that works. The goal is to think like innovators: identify a problem, study existing solutions, define a clear differentiator, and use AI well to help you design, refine, and implement an MVP. AI is your copilot. You are the pilot. Your role is to guide, instruct, question, refine, and make decisions. Do NOT just accept the first output from AI. What you will practise By the end of this session, you should be able to: • identify a small but meaningful problem • research similar existing apps or tools • define a clear value proposition and differentiator • use AI to help refine ideas and sharpen prompts • use GitHub Copilot in VS Code to help implement a small prototype • explain the next stage, business potential, and commercialisation path Tools for this activity Required • GitHub account • VS Code • GitHub Copilot extension in VS Code • ChatGPT or another LLM for idea refinement and prompt improvement Recommended setup path 1. First try to activate GitHub Education / Copilot Student if you are eligible. 2. If that is not ready in time, use GitHub Copilot Free. GitHub states that Copilot Free includes a limited monthly allowance, while verified students can access Copilot Student for free with more generous entitlements. Important constraints For this class: • Build a small app only • Keep it frontend-first • Avoid complicated backend setup • Avoid paid APIs • Do not build something that depends on buying tokens or adding credit cards • Your prototype should be small enough to create in one class session You may use AI to help design, plan, write, explain, debug, and improve the app. But your team must stay in control of the decisions. Task overview Your team will complete five parts: Part 1 — Define the problem Choose a small, realistic problem that can be solved with a creative, innovative simple app. Examples: • a student study-planning helper • a meeting note organiser • a personal habit tracker with better motivation design • a decision helper for choosing between options • a simple micro-learning or revision tool • a budgeting or expense categoriser for students • a wellbeing check-in app with smart prompts • a personal productivity dashboard for uni work Your app idea should be: • small • useful • clear • possible to prototype in one session Write this in one sentence: Our app helps [target user] solve [problem] by [approach]. Part 2 — Research existing solutions Before building, quickly research what already exists. Look for: • similar apps • competing tools • alternative workflows • current weaknesses in existing products Use search, app stores, or AI to help summarise what you find. Write down: • 2 or 3 existing solutions • what they do well • what they do poorly • where there is room for improvement Example prompt you can use: I want to build a simple app for [problem]. Find 2-3 existing apps or tools that solve a similar problem. For each one, summarise: - what it does - strengths - weaknesses - gaps or opportunities for improvement Keep it short and practical. Part 3 — Define your differentiator Now decide what makes your version worth building. You are not expected to invent something completely new. Innovation often comes from improving an existing idea in a better way. Your differentiator might be: • simpler user experience • clearer target audience • better workflow • better visual design • better onboarding • better use of AI during the design/build process • more personalised outputs • more practical value for students or young professionals Write: 1. Target user 2. Main pain point 3. Unique value proposition 4. Key differentiator Example prompt you can use Based on these existing solutions, help me define a clear differentiator. My target user is: My problem is: Existing tools are weak at: Suggest 3 possible differentiators that are realistic for a simple MVP. Part 4 — Use AI to refine your concept and plan Use AI to help sharpen the idea before coding. Your role is to guide AI well. Do not ask vague questions. Give context, constraints, and goals. Example prompt template I want to build a simple web app. Target users: Problem: Core features (maximum 3): Input: Output: Constraints: - simple - no paid API - suitable for a class prototype - frontend-first Please turn this into: 1. a short product spec 2. a simple feature list 3. an MVP scope 4. a step-by-step build plan Then improve the result. Ask AI to: • simplify it • reduce the scope • improve usability • make the idea more distinctive • suggest a better user flow Minimum expectation Your team should do at least: • one initial prompt • one refinement • one improvement or correction The point is not to get one answer. The point is to learn how to guide AI toward a better answer. Part 5 — Build the MVP in VS Code with GitHub Copilot Now create the prototype. Suggested stack: • HTML • CSS • JavaScript Or a very lightweight framework if your team already knows it. Use Copilot to help you: • create starter files • generate UI structure • add app logic • improve styling • debug errors • explain unfamiliar code • refactor messy code Good ways to use Copilot Ask for: • a small first version • one feature at a time • simple code with comments • clear file structure • explanation of code before accepting it Useful prompts inside VS Code Create a simple single-page web app for [idea]. Use clean HTML, CSS, and JavaScript. Keep the code easy to understand for university students. Improve the UI so it looks clean and modern, but keep it simple. Explain this code in plain English. Break this feature into smaller steps and implement them one at a time. Help me debug this issue and explain the cause. What to submit or show at the end of class Your team should be ready to show: 1. Your app idea In one sentence: • who it is for • what problem it solves • why it matters 2. Competitor / existing-solution scan Show: • 2 or 3 similar tools • what they do well • your opportunity to improve 3. Your differentiator Explain why your version is different. 4. Your prototype Show the MVP working. 5. Your AI collaboration evidence Be ready to explain: • how you used AI to refine the idea • how you used AI to improve the plan • how you used Copilot to implement the app • where AI was useful • where your team had to correct, refine, or reject AI output 6. Next-stage innovation plan If you had another 6 to 12 weeks, what would you do next? Examples: • improve user testing • add stronger personalisation • improve workflow design • build a better data model • introduce monetisation • improve trust, privacy, or usability • add analytics • expand the market 7. Business and commercialisation thinking Answer briefly: • Who would use this? • Who would pay for it, if anyone? • What business model could fit? • Why would someone choose this over alternatives? How this connects to INFO4444 This task is not just about building software. It is about applying innovation thinking. In this activity, you are practising: • identifying problems worth solving • scanning the market • analysing existing solutions • defining competitive differentiation • shaping an MVP • using digital tools to accelerate innovation • thinking about next-stage development and commercialisation This is what makes the activity relevant to IT Innovation and Creativity: • innovation is not only invention • creativity is not only idea generation • value comes from solving a problem in a clearer, better, and more usable way Guidance on using AI well Good mindset Use AI as a copilot, not as an autopilot. That means: • give clear instructions • set constraints • evaluate what comes back • refine weak ideas • question generic outputs • keep control of the direction Bad practice • copying the first answer • building without understanding • accepting code you cannot explain • making something too large to finish Good practice • ask AI to simplify • ask AI to compare options • ask AI to justify decisions • ask AI to improve clarity • ask AI to explain code and trade-offs • reject bad outputs and try again
